# 项目结构与研究问题

## 1. 先区分两套实际模型

| 项目 | 阶段 A：共享代价与早期消融 | 阶段 B：多长度与接收端后续处理 |
|---|---|---|
| 主文件 | model_jscm.py / run_experiments.py / distill.py | model_rdae.py / train_rdae.py / 后续各实验目录 |
| 信源 | 合成 CSI，2×32×32 实张量代表复矩阵 | 同一数据划分；逐样本实数 RMS 归一化后再除以 3 |
| 信道输入 | 64 个实符号 | 最多 64 个复符号，用 128 个实维存储 |
| 星座 | 学习的 16 点实数星座，或固定实 PAM 对照 | 固定 16-QAM，I/Q 各 4 个电平 |
| 反馈长度 | 主要固定 64 | Ns∈{16,32,64}，前缀发送、接收端补零 |
| 条件输入 | 普通共享无显式 SNR；条件共享给相对噪声幅度 | AF 同时用于编码器和解码器；主实验 cond=False 仍有 AF |
| 骨干 | 自建 CNN，另有 CsiNet 风格对照 | RD-JSCC 的 AE 骨架改编，含 BN、AF、5 个残差块 |
| 代表问题 | 0–20 dB 共享代价；蒸馏/重加权；BN 诊断 | BN 多条件变化；质量头；精修/重复；模块维护 |
| 主要 NMSE | 10log10(逐样本线性 NMSE 的平均) | 逐样本 NMSE_dB 的平均 |

两阶段都是有噪声、有限星座的端到端链路；后期换骨干与复星座，不能把前期数值直接接成同一条曲线。阶段 B 只移植 AE，不包含官方 VQ、扩散或官方完整数据流程，不能称官方 RD-JSCC 端到端复现。

## 2. 具体应用故事

考虑 FDD 大规模 MIMO 下行 CSI 反馈。UE 先获得下行 CSI，再通过有噪上行反馈把压缩后的信息交给 BS。为节省模型存储，部署一个覆盖多个反馈 SNR 的共享模型。第一步问：相对专用模型，代价出现在哪里，能否用较低维护成本改善？这是 Q1。

部署后平均曲线不能说明每次反馈都好。BS 对实际收到的 y 解码，再估计此次质量；若被判为差，可尝试启动本地修正器，或在明确的 UE 预检流程之后请求一次重复。这是 Q2。最后检查：Q1 改变了解码器的 BN 状态，Q2 的旧监测器和精修器是否也需要更新？这一步把两个问题连起来。

“收到许多 CSI”只用于说明接收端资源要合理使用。实际可以逐条处理：质量门限先在验证集固定，每条到达时判断；无需同时到达几百条。离线池按排序严格选 20% 的表格是预算诊断，与逐条固定门限策略要区分。

## 3. 数据与基本假设

原始路径：`simulation/data/{train,val,test}.npz`，键名 x，样本数 6000/1000/1000，形状 `(N,2,32,32)`。

`channel_data.py` 用 ULA 阵列响应、多径时延抽头生成天线—时延矩阵，再对时延维做 DFT，输出空—频域复信道的实部/虚部。它不是 COST2100 实测数据，也不是把天线维做角域变换后的矩阵。文件头“角—时延域”用语不够精确，学习时按实际运算理解。

主实验假设 UE 端已知理想 CSI，反馈信道为 AWGN；后面有估计误差敏感性探索，但不能改写主结果的假设。反馈 SNR、UE 下行估计误差、下行数据传输 SNR 是三个不同量。

## 4. 训练时和运行时

| 模块 | 训练时 | 运行时 |
|---|---|---|
| CSI 编解码器 | H 是监督；编码器和解码器共同反传；信道通过随机噪声模拟 | UE 持有 H；BS 持有 y、SNR/长度条件与自己的模型 |
| 学习星座（阶段 A） | 星座参数也更新 | 使用已学好的点集 |
| 固定 QAM（阶段 B） | 无可训练星座参数，STE 近似反传 | 真的映射到有限点集 |
| BN 条件重标定 | 用源域训练数据跑链路、更新接收端统计量，无梯度 | 按已知条件选/插值统计量 |
| BS 质量头 | 用真实误差作回归标签，编解码器冻结 | 只用 y 的特征与条件，不用真实 H |
| BS 精修器 | 用 H 训练残差修正，原链路冻结 | 用原重建、接收特征、y 和条件作一次本地计算 |
| UE 代理 | 离线蒸馏轻量解码器 | UE 用本地 H 与干净码字预测质量；看不到这次反馈噪声 |

联合训练没有让真值 H 出现在 BS，也没有让 UE 预知某次噪声。两端的信息差别依然存在。解码器特征是 y 的确定性变换，使用特征改善学习效率不代表获得了额外反馈信息。
